# เทสต์ของ DrugCount

```
python tests/run.py                 # ทั้งหมด
python tests/run.py zero ask        # เฉพาะชุดที่ชื่อมีคำนี้
python tests/run.py -v zero         # พร้อมข้อความทุกบรรทัดที่ชุดนั้นพิมพ์
```

ต้องใช้ล่ามที่มี PySide6, OpenCV, numpy และ onnxruntime — ตัวเดียวกับที่รันแอปบน PC
(`.venv\Scripts\python.exe` ในโฟลเดอร์โปรเจกต์ — ตัวเดียวกับที่ `find-python.bat` หาให้ไฟล์ .bat ทุกตัว)

ทุกชุดเป็นสคริปต์ที่ขับ**ของจริง** ไม่ใช่ของปลอม: `Window` จริงกับกล้องปลอม, `Screen` จริงที่
วาดภาพจริงออกมา แล้วพิมพ์ `ok` หรือ `FAIL` ทีละข้อ และจบด้วย exit code ที่ไม่ใช่ศูนย์ถ้ามีข้อไหนพลาด

## ชุดที่มี

| ชุด | ดูแลอะไร |
|---|---|
| `test_align` | จุดลงตรงเม็ดยาไหม — วัดตั้งแต่พิกัดกล้องจนถึงพิกัดบนจอ ผ่านสะพานจริง |
| `test_arming` | ระหว่างอยู่ในหน้าตั้งค่ากล้อง ห้ามบันทึกและห้ามเก็บรอบ |
| `test_ask` | เปลี่ยนจำนวนขณะมีรอบเก็บไว้ ต้องถามก่อน และฉากหลังต้องหรี่จริง |
| `test_corners` | เรขาคณิตของกรอบ 4 จุด และสองเครื่องต้องคิดตรงกัน |
| `test_dead_camera` | กล้องหยุดกลางคัน จอฝั่งกล้องต้องดำและบอกเหตุ แล้วกลับมาเองเมื่อกล้องใช้ได้ — ทั้งสองเครื่อง |
| `test_decode` | การตัดกล่องซ้ำแบบเร็ว ต้องได้เลขเท่าเดิม |
| `test_flip` | พลิกภาพให้ถูกด้าน โดยไม่ขยับสิ่งที่ใช้นับ |
| `test_marks` | เลื่อนถาดแล้วจุดต้องตามไปด้วย ไม่ค้างที่เดิม |
| `test_pace` | จังหวะเรียกโมเดล นับจากของจริง ไม่ใช่จากสูตร |
| `test_pad` | แป้นป้อนจำนวน: กดนอกกรอบต้องไม่ปิด ปิดได้ทางเดียวคือตั้งใจปิด |
| `test_partial` | บันทึกทั้งที่ยังไม่ครบ ขณะมีรอบค้างอยู่ ต้องถามก่อน |
| `test_phone_rounds` | การนับหลายรอบบนมือถือ ขับแบบเดียวกับที่สะพานขับจริง |
| `test_quick_draw` | ทางลัดของการวาดจอมือถือ (ย่อเฉพาะส่วนที่เปลี่ยน) ต้องได้ภาพตรงกับทางเต็มทุกพิกเซล ในหลายขนาดจอ |
| `test_quit` | ปุ่มปิดโปรแกรม: มีอยู่ทุกหน้า และต้องกดสองครั้ง |
| `test_retarget` | เปลี่ยนจำนวนหลังเทลงกระปุกไปแล้ว |
| `test_roi_flow` | การวางกรอบนับในหน้าตั้งค่ากล้อง ทั้งบน PC และมือถือ |
| `test_rotate` | หมุนภาพ 180° (กล้องติดฝั่งตรงข้ามถาด): หมุนแค่ภาพที่แสดง จุดกับการแตะต้องตรงเม็ดเดิม โมเดลและระเบียนไม่เปลี่ยน บันทึกเฉพาะตอนกดบันทึก ยกเลิกแล้วกลับค่าเดิม — ทั้งสองเครื่อง |
| `test_rounds` | การนับหลายรอบบน PC |
| `test_zoom` | ซูมในหน้าตั้งค่ากล้อง: หน้าหลักไม่มีแถบซูม, บันทึกลงไฟล์เฉพาะตอนกดบันทึก, ยกเลิกแล้วกลับค่าเดิม, ซูมแล้วต้องล้างกรอบเดิม — ทั้งสองเครื่อง |
| `test_zero` | ถาดว่างต้องบันทึกไม่ได้ — ทั้งสองเครื่อง |

`run.py` ปิดท้ายด้วย `model3.tools.simulate_phone` ซึ่งไม่ใช่เทสต์ แต่เป็นการขับสะพานมือถือ
ทั้งเส้นด้วย ONNX จริงบน PC ถ้าชิ้นส่วนไหนไม่เข้ากันมันจะโยน exception ออกมาตรงนั้น

## เรื่องที่ควรรู้ก่อนเขียนชุดใหม่

**แต่ละชุดรันแยกโปรเซส** เพราะมันแก้ตัวแปรระดับโมดูล (`RECORDS`, `SETTINGS`) และวางผัง
หน้าจอมือถือตามขนาดจอที่ตัวเองเลือก ถ้าใช้ล่ามร่วมกัน ของที่ชุดหนึ่งทิ้งไว้จะไปตัดสินผลของอีกชุด

**แต่ละชุดมี timeout** เพราะกล่องคำถามที่ไม่มีใครตอบจะรอตลอดกาล — ตอนเพิ่มคำถาม
"เปลี่ยนจำนวน" เข้าไป มันทำให้สองชุดค้างยาว และชุดที่ค้างหน้าตาเหมือนชุดที่กำลังทำงานละเอียด
`run.py` จะรายงานว่า `HUNG` แทนที่จะรอ

**ใช้โฟลเดอร์ชั่วคราวของตัวเองเสมอ** เคยมีชุดที่อ่าน `app/settings/roi-cam0.json` ของจริง
แล้วกฎ "ไม่มีกรอบ = นับไม่ได้" เลยผ่านโดยไม่เคยถูกทดสอบจริงสักครั้ง

**เทสต์ที่ไม่เคยพังคือเทสต์ที่ยังไม่รู้ว่าตัวเองพัง** ตอนเพิ่มกฎ memo key ผมถอดโค้ดที่แก้ออก
แล้วรันซ้ำเพื่อดูว่ามัน `FAIL` จริงก่อน แล้วค่อยใส่กลับ — ทำแบบนี้กับทุกข้อที่ตั้งใจให้ดักบั๊ก
